# AVOGADRO security review

**Review date:** 2026-10-21
**Scope:** source review of Phase 3 API/SIWE, campaign persistence, worker/outbox, runner, Compose/DB grants, artifact handling, and contract ingestion.
**Disposition:** The current implementation is a local, trusted-fixture prototype. It does not enable user-supplied source or broadcast transactions. Several source-level protections are present, but PostgreSQL migration/grant behavior and the worker container boundary were not runtime-validated in the Phase 3 environment. Do not treat configuration inspection as proof of runtime isolation.

## Findings

## Controls observed in source

- Campaign input is strict and fixture allowlisted. API accepts no source, shell command, Forge argument, RPC URL, working directory or environment variable. It derives fixture source/execution digests; client-provided digests are not trusted.
- Worker queue messages contain only a UUID `campaignId`; the worker reloads authoritative fixture/config from PostgreSQL, leases the attempt, polls cancellation and renews the lease. Worker database projections are narrow and migration grants are column-scoped when the role exists at migration time.
- Runner accepts only compiled-in fixtures and named tests, copies the repository contracts tree into a temporary scratch directory, rejects source-tree symlinks while digesting, uses configured absolute Forge/solc paths, checks tool versions, passes a fixed argument list and a minimal offline environment, starts a process group, caps stdout/stderr, enforces Forge timeout, attempts process-group termination on cancellation/timeout, hashes bounded output and removes scratch in `finally`.
- Runner's Forge invocation has no `--broadcast`, public RPC, signer, wallet or credential. It sets `FOUNDRY_OFFLINE=true` and runs local test-EVM fixtures. Compose connects worker only to the internal `worker-isolated` network for Redis/PostgreSQL. The worker has no configured RPC or object-store credentials. This source/configuration inspection does not prove runtime egress denial.
- SIWE uses 192-bit random nonces, configured domain/URI/chain 4663, a five-minute issued-at window, signature verification through `siwe`, one-use DB nonce consumption, expired nonce cleanup on issuance, random session/CSRF tokens with hashed persistence, HttpOnly/SameSite=Strict cookies, CSRF header/cookie matching for mutations, DB expiry/revocation checks, logout revocation, production HTTPS/domain validation and per-process auth endpoint throttles. Tests cover valid wallet signature, domain/URI/chain mismatch, stale `issuedAt`, nonce reuse/replay and rate limits.
- Campaign reads, cancellation and replay are owner-scoped in the store. Replay copies recorded fixture/config/seed without request overrides. Test doubles cover route contracts but do not prove DB behavior.
- Queued cancellation sets the campaign and queued attempts to terminal `cancelled` and writes an event in one DB transaction. Running cancellation uses a cooperative request flag. The transition is source-reviewed; no PostgreSQL cancel/lease race test ran.
- Ingestion restricts RPC requests to Robinhood Chain's official HTTPS host, validates chain ID 4663, performs read-only JSON-RPC methods, bounds response size/time and rejects redirects for both RPC and explorer requests. RPC egress controls have not been runtime-tested.

## Validation evidence and limits

Prior reported checks in the engineering session: root suite 12 passed, 1 skipped; API tests 2 passed; runner unit tests 6 passed; real Redis/BullMQ worker suite 6 passed; real Forge fixture integration 1 passed with repeated same-seed invariant replay producing the same emitted counterexample sequence and hash. These results were reported by the orchestrator/QA work; they were not independently rerun during this documentation review.

Not runtime-validated here: Docker image build/start, Compose network policy, PostgreSQL migrations/effective grants, DB-backed campaign execution, worker container isolation, S3-compatible object storage, hostile process teardown/escape/egress, SIWE proxy behavior, and source-to-bytecode equivalence. A local Docker daemon and usable disposable PostgreSQL were unavailable in the prior execution environment. No coverage or scan finding beyond the observed fixture test is implied.

## Required runtime checks before launch

1. Start disposable PostgreSQL, create `avogadro_worker` before migrations, apply migrations from scratch, connect as that role, and execute lease/renewal/result/retry/outbox flows. Verify access to users, sessions, contracts, contract sources and secrets is denied.
2. Keep the real Redis queue verification and validate Redis ACLs/network policy against the intended deployment configuration; local Compose Redis is development infrastructure.
3. Build/start the worker container and execute passing and deliberate invariant-violation fixtures with the checksum-verified Forge/solc. Verify no mainnet/public RPC route or broadcast capability.
4. Test cancellation before lease, racing with lease, during setup, during Forge, at timeout and during worker shutdown; verify queued cancellation is terminal and process descendants are gone.
5. Exercise output floods, CPU/memory/PID/disk pressure, repeated maximum-cost campaigns and cleanup; then add and verify admission limits and bounded retained data.
6. Test SIWE expiry/not-before, DB-backed revocation, cookie expiry/attributes, CSRF, production HTTPS and shared rate limits behind the trusted proxy.
7. Run adversarial filesystem/network/namespace/capability checks under the actual deployment boundary. Compose configuration inspection alone is insufficient.
8. Recompile imported source against recorded settings and compare runtime bytecode; retain tests rejecting redirected RPC/explorer requests.

## Launch blockers

- Do not execute imported source or user build scripts in the current worker container.
- Do not call campaign execution operational until migrations, worker grants and a persisted API → queue → worker → result flow are verified against PostgreSQL.
- Add shared rate limits/admission controls before multi-replica or public deployment.
- Do not claim source-to-bytecode proof, production worker isolation, S3 artifact export or pinned-mainnet fork testing; these remain unimplemented or unverified.
