# AVOGADRO security review

**Review date:** 2026-10-21
**Scope:** source review of Phase 3 API/SIWE, campaign persistence, worker/outbox, runner, Compose/DB grants, artifact handling, and contract ingestion.
**Disposition:** The current implementation is a trusted-fixture prototype. Contract ingestion can retain explorer-verified source and ABI, but imported source is not accepted by the campaign runner and cannot be compiled or executed by it. Campaign Forge runs execute repository-owned fixtures only. The ordinary worker container is not a strong hostile-code sandbox. Do not enable imported Solidity execution until per-job isolation has been implemented and validated against the exact runtime.

## Findings

| Severity | Finding | Evidence and impact | Required closure |
|---|---|---|---|
| Critical before untrusted execution | Worker container is defense in depth, not a per-job hostile-code sandbox. | `apps/worker/Dockerfile` and `docker-compose.yml` configure a non-root user, read-only root filesystem, dropped capabilities, `no-new-privileges`, PID/CPU/memory limits and bounded no-exec tmpfs. The worker is attached to the internal Compose network shared with PostgreSQL, Redis and S3Mock; its environment includes database and object-store credentials. The runner gives Forge a reduced environment, but the worker container itself retains those credentials and service reachability. There is no per-job microVM, custom seccomp profile, separately managed scratch mount, or executed adversarial egress/escape test. | Keep imported source and user build scripts disabled. ## Controls observed in source

- Campaign input is strict and fixture allowlisted. API accepts no source, shell command, Forge argument, RPC URL, working directory or environment variable. It derives fixture source/execution digests; client-provided digests are not trusted.
- Worker queue messages contain only a UUID `campaignId`; the worker reloads authoritative fixture/config from PostgreSQL, leases the attempt, polls cancellation and renews the lease. Worker database projections are narrow and migration grants are column-scoped when the role exists at migration time.
- Runner accepts only compiled-in fixtures and named tests, copies the repository contracts tree into a temporary scratch directory, rejects source-tree symlinks while digesting, uses configured absolute Forge/solc paths, checks tool versions, passes a fixed argument list and a minimal offline environment, starts a process group, caps stdout/stderr, enforces Forge timeout, attempts process-group termination on cancellation/timeout, hashes bounded output and removes scratch in `finally`.
- Runner's Forge invocation has no `--broadcast`, public RPC, signer, wallet or credential. It sets `FOUNDRY_OFFLINE=true` and runs local test-EVM fixtures. Compose connects the worker only to the internal `worker-isolated` network for Redis/PostgreSQL/S3Mock; Compose also supplies DB and object-store credentials to the worker process. The Forge child gets a reduced environment, but that does not prove the worker boundary or prevent access to internal services. Configuration inspection does not prove runtime egress denial.
- SIWE uses 192-bit random nonces, configured domain/URI/chain 4663, a five-minute issued-at window, signature verification through `siwe`, one-use DB nonce consumption, expired nonce cleanup on issuance, random session/CSRF tokens with hashed persistence, HttpOnly/SameSite=Strict cookies, CSRF header/cookie matching for mutations, DB expiry/revocation checks, logout revocation, production HTTPS/domain validation and per-process auth endpoint throttles. Tests cover valid wallet signature, domain/URI/chain mismatch, stale `issuedAt`, nonce reuse/replay and rate limits.
- Campaign reads, cancellation and replay are owner-scoped in the store. Replay copies recorded fixture/config/seed without request overrides. Integration tests exercise the authenticated API → PostgreSQL → Redis/BullMQ → trusted fixture worker → S3Mock flow in CI; they do not prove production provider behavior or hostile-code isolation.
- Queued cancellation sets the campaign and queued attempts to terminal `cancelled` and writes an event in one DB transaction. Running cancellation uses a cooperative request flag. The transition is source-reviewed; no PostgreSQL cancel/lease race test ran.
- Ingestion restricts RPC requests to Robinhood Chain's official HTTPS host, validates chain ID 4663, performs read-only JSON-RPC methods, bounds response size/time and rejects redirects for both RPC and explorer requests. RPC egress controls have not been runtime-tested.

## Validation evidence and limits

The prior Phase 6 report recorded CI verification of typecheck, lint, frontend build, disposable PostgreSQL migrations/grants, Redis/BullMQ, pinned Foundry, and authenticated campaign acceptance through S3Mock, including deterministic replay and owner checks. This review did not rerun CI or independently reproduce those checks. Treat them as recorded CI results, not as worker isolation evidence.

Not runtime-validated here: Docker image build/start, Compose network policy, runtime credentials exposure to Forge/worker, worker container isolation, hostile process teardown/escape/egress, real S3 IAM/lifecycle behavior, SIWE proxy behavior, and source-to-bytecode equivalence. Current environment did not provide Docker/Podman, so this review could inspect configuration only. No coverage or scan finding beyond the observed fixture test is implied.

## Required runtime checks before launch

1. Keep imported Solidity and user-controlled Foundry config, scripts, remappings and build hooks disabled.
2. Build a disposable execution service per job (microVM or equivalent) with no production or application credentials, no access to API/DB/Redis/object-store networks, strict egress denial, read-only toolchain, isolated writable scratch and teardown on every outcome.
3. Execute adversarial denial tests inside the exact runtime for filesystem escape, metadata/internal address access, DNS/TCP egress, syscall/capability boundaries, CPU/memory/PID/disk exhaustion, timeout, child-process cleanup and cross-job persistence. Fail closed if any control is unavailable.
4. Keep the real Redis queue verification and validate Redis ACLs/network policy against the intended deployment configuration; local Compose Redis is development infrastructure.
5. Validate the CI-reported disposable PostgreSQL grants and authenticated campaign flow; test that the untrusted execution boundary cannot access these services or their credentials.
6. Validate real S3 scoped IAM and lifecycle behavior; S3Mock behavior alone is insufficient for those claims.
7. Recompile imported source against recorded settings and compare runtime bytecode; reject unsupported constructors, dependencies, proxies and initialization assumptions with explicit status rather than silently substituting behavior.
8. Test SIWE expiry/not-before, DB-backed revocation, cookie expiry/attributes, CSRF, production HTTPS and shared rate limits behind the trusted proxy.

## Launch blockers

- Do not execute imported source or user build scripts in the current worker container. The container shares access to internal services and receives their credentials.
- Do not claim hostile-workload isolation based on Compose settings or trusted-fixture CI. A disposable, credential-free execution boundary and adversarial denial results are required.
- Do not treat disposable CI verification as production deployment approval; validate the deployed database and runtime independently. Trusted-fixture campaign validation does not imply imported-contract execution readiness.
- Add shared rate limits/admission controls before multi-replica or public deployment.
- Do not claim source-to-bytecode proof, production worker isolation, S3 artifact export or pinned-mainnet fork testing; these remain unimplemented or unverified.
